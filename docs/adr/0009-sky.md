# 0009 - Sky: a procedural fullscreen pass, a six-stop ramp, and a simple sun path

- Status: accepted
- Date: 2026-11-26
- Decides for: 3.4 (sun model), 3.6 (skybox), 3.7 (fog), C17-C19, C24

## Decision

| Question | Answer |
|---|---|
| Technique | **procedural fullscreen triangle**, view ray reconstructed from the camera basis; no cube map, no geometry |
| Cost of that choice | measured at **0.006 ms/frame at 1280x720** and **0.011 ms at 1920x1080** (sky only, vsync off) against a 1.0 ms budget |
| Colours | six sRGB palette stops blended by sun elevation; converted to linear once (ADR 0008) |
| Gradient | `mix(horizon, zenith, pow(max(dir.y, 0), 0.45))` |
| Sun disc | `smoothstep(0.99985, 0.99995, dot(dir, sun_dir))` (about 0.5 degrees) plus a glow `pow(dot, 220) * 0.55` |
| Below the horizon | clamped to the horizon colour, so a gap under the terrain reads as haze, never as black |
| Sun path | `elevation = E_max * sin(2*pi*t)`, `azimuth = 90 + 360*t` degrees from north; `E_max = 62`, cycle 600 s |
| Cameras | the sky is drawn at infinity: the pass ignores the camera position, only its basis |

## Why procedural, with the numbers

A cube map is the usual answer, and it is measurably *not* worth it here:

| Resolution | Procedural | Cube map (256^2 faces) |
|---|---|---|
| 1280x720 | 0.006 ms/frame | 0.005 ms/frame |
| 1920x1080 | 0.011 ms/frame | 0.011 ms/frame |

The saving is around one microsecond, which is 0.01 % of an 8.33 ms frame, and it buys a fixed
resolution, six textures to keep in sync with a moving sun, and no way to key the colours to
sun elevation without re-baking. The procedural pass also shares the exact ramp function with
the fog (3.7) and the ambient term (3.5), so those three cannot drift apart.

Rejected as well: a real scattering model (Preetham or Hosek). It needs turbidity, Rayleigh and
Mie parameters, adds tens of ALU ops and a colour-science rabbit hole, and the brief is a
stylised voxel game with four clearly different times of day, not a physically accurate sky.
Recorded so it is not revisited from memory: revisit only if realism becomes a stated goal.

## The colour ramp

Six sRGB stops:

| Stop | sRGB |
|---|---|
| night zenith | 8, 10, 23 |
| night horizon | 15, 17, 28 |
| twilight zenith | 25, 35, 76 |
| dawn horizon | 229, 119, 61 |
| day zenith | 81, 127, 204 |
| day horizon | 173, 198, 229 |

Mixed by three smoothsteps on sun elevation (bands chosen so the sky keeps its warmth until the
sun is well up):

- `t_night = smoothstep(-18, -6, el)` - below -18 it is night, above -6 the sky has colour
- `t_day = smoothstep(0, 25, el)` - full daylight only by 25 degrees
- `w_warm = smoothstep(-8, 0, el) * (1 - smoothstep(4, 16, el))` - a warm horizon band that peaks
  around sunrise and sunset

The resulting table, printed by the probe in sRGB 0-255:

| Sun elevation | daylight | zenith | horizon | sun |
|---|---|---|---|---|
| -90 | 0.00 | 7, 10, 22 | 15, 17, 28 | 0, 0, 0 |
| -18 | 0.00 | 7, 10, 22 | 15, 17, 28 | 0, 0, 0 |
| -12 | 0.50 | 16, 22, 49 | 122, 68, 44 | 127, 70, 35 |
| -6 | 1.00 | 25, 35, 76 | 229, 119, 61 | 255, 140, 71 |
| 0 | 1.00 | 25, 35, 76 | 229, 119, 61 | 255, 140, 71 |
| 3 | 1.00 | 27, 39, 81 | 229, 119, 61 | 255, 144, 77 |
| 8 | 1.00 | 39, 57, 107 | 225, 124, 71 | 255, 164, 108 |
| 20 | 1.00 | 75, 117, 190 | 179, 190, 211 | 255, 231, 208 |
| 45 | 1.00 | 81, 127, 204 | 173, 198, 229 | 255, 242, 224 |
| 62 | 1.00 | 81, 127, 204 | 173, 198, 229 | 255, 242, 224 |
| 90 | 1.00 | 81, 127, 204 | 173, 198, 229 | 255, 242, 224 |

Every row is a blend of the stops above, so no elevation in between can jump. `daylight` is the
`t_night` term and is what the ambient (3.5) and fog (3.7) scale by.

## The sun path

`t01` is the position in the cycle: 0 sunrise, 0.25 noon, 0.5 sunset, 0.75 midnight.

| t | direction (x east, y up, z south) | elevation | azimuth |
|---|---|---|---|
| 0.000 | (1.000, 0.000, 0.000) | 0.0 | 90 (east) |
| 0.125 | (0.510, 0.693, 0.510) | 43.8 | 135 |
| 0.250 | (0.000, 0.883, 0.469) | 62.0 | 180 (south) |
| 0.375 | (-0.510, 0.693, 0.510) | 43.8 | 225 |
| 0.500 | (-1.000, 0.000, 0.000) | 0.0 | 270 (west) |
| 0.750 | (0.000, -0.883, -0.469) | -62.0 | 0 (north, below the horizon) |

This is a stylised arc, not astronomy: no declination, no latitude, no equation of time. It gives
what the brief needs - rises east, peaks in the south, sets west, spends half the cycle below the
horizon - with two numbers a human can reason about. A 62 degree maximum is a Swedish summer noon;
the cycle length (600 s default) is a tunable, and 3.10 owns the ability to pin an exact sun.

## Consequences

- The sky shader needs the camera basis and nothing else; it never reads the depth buffer, so it
  runs first with depth test and depth write off.
- `ramp()` returns **linear** colours (ADR 0008) plus a `daylight` scalar, and is the single
  source for the sky, the fog and the ambient term.
- `sunDirection()` is pure, so 3.10's pinning and 3.9's screenshots are deterministic.
- The disc is deliberately soft-edged at 0.5 degrees: at 1280x720 it is a few pixels across, and
  a hard edge would crawl as the sun moves.
- Below the horizon the pass returns the horizon colour; the reference image shows the resulting
  flat band, which the terrain covers in normal play.
